- Each `Scene` will determine what the user `Intent` was based on the `inputHistory`
immediately following the last update (though I don't believe it *must* follow input handling) along with any relevant

Intent handling:
- As before, each `Scene` handles the `Intent` on its own. In every case, it checks the validity of
and grabs the parameters passed with the `Intent` and performs the necessary actions to enact the `Intent`.

## Architecture

### Component Flow

<!--
Describe how data flows between major components.
Example: SDL Event → Input History → Intent → Scene Stack → Widgets → Renderer
-->

The sole inputs to the system are the settings file (as applicable) and the `sdl.Event`s.

If a settings file is loaded, it changes the `programSettings` to match the data stored in the file 
(which is just a JSON representation of the `programSettings`.)

If an event is given by `sdl.PollEvent()` in the main loop, it passes through input registration,
input determination, and then input handling as described in the overview.

As applicable, an `Intent` may trigger a `Scene` change via a `Scene`'s `handleIntent()` function.
If this happens, the `Scene` is either replaced entirely (i.e. removed from the `sceneStack` with a new `Scene` pushed),
or a `Scene` is pushed on top of it such that if said `Scene` is eventually popped,
the original `Scene` will be active again.

When a `Scene` proceeds to `handleIntent()`, it may pass the `Intent` down to its `Widget`s
(if applicable, stored in `data.([*type]).widgets`) which can also `handleIntent` as needed.

All `Scene`s and `Widget`s have access to the renderer via the `programContext` but
as of now only the `plotWidget` actually accesses the renderer, for the sake of
regenerating the fractal plot upon calls to `update()`. Eventually, the widgets comprising
the GUI (incl. `GUIBaseWidget`) will also access the renderer.

### Key Components

- **Input System**: Takes raw `sdl.Event`s and converts them to input states of `inputStateType`,
then stores them in an `inputHistory` of `inputHistoryType`.
- **Intent System**: Takes an `inputHistory` and figures out what the user's `Intent` was, then handles
the `Intent` per-scene, involving widgets as needed. Currently only considers the most recent user intent and
throws away the rest during processing.
- **Scene System**: Manages the current state of the program with respect to graphical components and behavior. Part of 
the overall `programContext`.
- **Widget Tree**: Stores the `Widget`s for a given `Scene`, including their children (stored in the `Widget` struct).
`Widget`s can delegate actions (such as `handleIntent()`) to their children, and so forth.
- **Rendering**: The renderer can be interacted with directly by anything with access to `programContext`.
Typically, `Widget`s with a texture will interface with the renderer to display themselves.
